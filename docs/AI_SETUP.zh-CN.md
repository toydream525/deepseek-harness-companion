# 交给 AI 配置 DSH 伴航

[返回首页并复制短任务](../README.md#交给-ai-配置) · [详细配置说明](GETTING_STARTED.zh-CN.md) · [English](AI_SETUP.en.md)

把仓库的 [详细配置说明](GETTING_STARTED.zh-CN.md) 与[内置从零配置指南](../resources/guides/从零配置指南.md)一并交给能操作本机的 AI。以下是更细的执行与验收任务，可整段复制。**模型 GGUF 由你从指南对应的 Hugging Face 页面自行下载**；AI 检查并复用文件，不擅自重复下载模型。

```text
你现在在这台 Windows 电脑上实际配置当前稳定版或已安装版 DSH 伴航。请先核对软件实际版本，再阅读对应版本仓库的 README.md、docs/GETTING_STARTED.zh-CN.md、resources/guides/从零配置指南.md；不要只解释步骤，要操作并报告可核实的结果。

1. 检查系统、CPU/GPU、驱动、RAM/VRAM，以及已存在的 llama.cpp、GGUF、模板、Node.js 和 DSH。不要假定这台机器与参考 RTX 4080 电脑相同；不要清理或覆盖已有模型和程序。优先复用可用资源，确需隔离时复制到独立目录。
2. 缺少引擎、Node.js、DSH 时，按指南中的官方来源取得适合这台机器的完整文件；有合适现成文件就不重复下载。Qwen 模型权重请让我从 README 里的 Hugging Face 页面手动下载准确 GGUF，再由你核对文件完整性与分片并绑定。froggeric 模板只用指南注明的固定提交，先复用已有文件。
3. 安装或解压伴航；绑定并检测 llama-server.exe；把 GGUF 入库。若选择 Qwen 参考方案，导入三个稳定预设并确认模板及模型路径都指向实际文件；写作档缺失时保持待绑定，不宣称已经测试。其他模型用通用参数，从保守上下文和显存设置开始。
4. 启动模型，看到本地 API 就绪后，在试聊里实际生成回答；记录生效模型、预设、上下文、输出限制、真实响应与有意义的错误。单纯文件存在、进程存在或端口开放不足以算通过。
5. 如果我要使用 DSH，检测 Node.js 与完整 DSH 本地目录，连接当前实例的认证会话，注册本地提供方，设为新会话默认，再实际创建新会话对话。外部 DSH 不应被擅自停止；如果认证缺失，提示我在软件里输入原链接，不从外部日志提取令牌。
6. 每一步失败都写具体原因、影响和下一次可执行动作。最后给我“已完成/未完成”清单、实际选择的文件与版本、哪些仅为参考、仍需我决定的事项。高级 64K/KV Streaming/MTP/视觉档默认关闭，不能把未测功能写成通过。

保密：不要读取、复制、展示、上传 API 密钥、DSH 认证链接、聊天记录、个人配置或模型权重。需要凭证时让我在应用输入框自己填写。不要为了方便而关闭认证、扩大监听地址、修改系统级代理或全局脚本策略。
```

验收时至少分别确认：引擎检测、GGUF 完整、导入结果、本地真实回答；需要 DSH 时再确认认证、提供方、新会话默认和实际对话。原 Qwen 配方更完整的十项验收列在[内置指南](../resources/guides/从零配置指南.md)。
