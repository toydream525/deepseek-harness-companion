# Open-source build and release guide

This document describes the public source of DSH 伴航 / Harness Companion. The
application is an independent community project and is not affiliated with or
endorsed by DeepSeek. Its original code is MIT-licensed; dependencies retain
their own licenses in `THIRD-PARTY-NOTICES.md`.

## Build on Windows

Use Windows x64 and CPython 3.12. Build paths can be anywhere; a particular
drive letter is not required. In a PowerShell prompt at the source root:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m pip install --target manager\_vendor -r requirements-vendor.txt
.\.venv\Scripts\python.exe manager\build_exe.py
```

The v0.2.0 build writes `release/DSH-Companion/` and
`release/DSH-Companion-v0.2.0-windows-x64.zip`. The ZIP includes the interpreter and
Qt libraries but not optional llama.cpp, Node.js, DeepSeek Harness, models, or
GPU runtimes. The fixed component-update manifest and npm integrity lock are
instructions for opt-in downloads, not installed third-party runtimes. Run the
EXE only from an extracted copy, because the application
creates local state when launched. Consult `README.md` or `README.en.md` for
first use and official optional-component links.

To create the separate Windows installer, install
[Inno Setup 6.7.3 from its official download page](https://jrsoftware.org/isdl.php)
and run the script after the clean onedir build:

```powershell
.\tools\build_installer.ps1
```

This compiles `installer/DSH-Companion.iss` into
`release/DSH-Companion-Setup-v0.2.0-windows-x64.exe`. The installer contains
the onedir application, not a Python/Qt/DSH/Node/model downloader. It has no
post-install launch or autorun action. Review its source and test an actual
install and uninstall before release; a successful compiler exit alone does
not establish that installed software works or personal data is preserved.

`manager/_vendor` is generated by the separate pinned dependency install; it
is intentionally absent from the public source archive. The PyInstaller spec
copies needed modules and package metadata while excluding Python bytecode
caches and vendor command-line launchers. Build dependency versions are pinned
for repeatability, but upstream wheels and tools must remain available; this
is not a bit-for-bit reproducible-build guarantee.

## What to publish

The source archive is produced with `tools/stage_public_source.py`, which
copies only explicit application files, documentation, icons, license texts,
and example resources. It rejects personal state and likely secrets. It does
not copy the development folder wholesale. Review the generated manifest and
`deepseek-harness-companion-v0.2.0-source.zip` before uploading them to GitHub.

```powershell
.\.venv\Scripts\python.exe tools\stage_public_source.py ..\public-source-review-v0.2.0
```

Choose a destination that does not already exist. The script writes a source
tree, `SOURCE-MANIFEST.sha256`, and the ZIP there. The public Git checkout
should contain the same approved source files; do not initialize a repository
in or upload the unrestricted development folder.

For a GitHub Release, attach the source archive, a tested Windows Setup EXE,
the portable ZIP, and the importable Qwen reference recipe, with their SHA-256
checksums in the release notes. State the tested Windows version,
application version/commit, Python and Qt versions, and known limitations.
Confirm the portable ZIP passes a clean extracted launch and contains
`LICENSE`, `THIRD-PARTY-NOTICES.md`, license texts, four built-in guide/example
files and the importable recipe. Confirm the Setup EXE installs the same application, starts
only when chosen by the user, uninstalls without deleting user models or
configuration, and retains the Inno Setup license notice. Keep screenshots free of personal paths, model names,
credentials, chats, and logs.

The upstream DeepSeek Harness project is
<https://github.com/deepseek-ai/deepseek-harness>. Users obtain it, Node.js,
llama.cpp, templates, and model weights separately or explicitly prepare an
available pinned version from the in-app Component Updates page. Node.js and
GPU drivers remain official guidance plus user-selected paths. Do not upload any original
deployment attachment, local configuration, credentials, model files, or
third-party runtime from the development machine.

## Qt distribution notes

The packaged Qt DLLs and plugins are kept as replaceable shared files in
`_internal/PySide6`. Their LGPL/GPL terms and exact upstream source locations
are in `THIRD-PARTY-NOTICES.md`. The build must exclude unused GPL-only Qt
Virtual Keyboard binaries; the final ZIP audit checks this. Qt PDF is also
excluded because the application does not use it and that module brings
additional PDFium notices. Do not remove applicable third-party license
materials when repackaging.
